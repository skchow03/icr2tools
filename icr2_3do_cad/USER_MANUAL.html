The User's Guide • Contents and Index • 1995 Edition*

ICR2 3DO CAD

A complete guide to viewing, inspecting, and editing Papyrus 3D models for IndyCar Racing II and CART Racing.

*The look is from 1995. The application is modern, the help is unofficial, and no actual Windows 95 installation is required.

Welcome to ICR2 3DO CAD, a visual editor for .3DO binary models and editable Papyrus/N3 .3D source files. Examine a car from any angle, inspect polygon draw order, make changes to source, and export a compiled model for testing in the simulator.

This Help file describes the current PySide6/OpenGL application—not the original Papyrus game's menus. It is stored on your computer and works without an Internet connection. Even a 14.4 kbps modem can keep up.

Important: The CAD preview is not a perfect reproduction of the ICR2 rendering engine. A model that looks right here still needs to be checked in the game. Keep backups of working carsets and tracks.

See also: A five-minute tour · Saving versus exporting · Troubleshooting

1. A Five-Minute Tour

  1. Start the program. On Windows, run RUN_ME_WINDOWS.bat, or start python icr2_3do_cad.py from the tool's folder. Python 3.10+, installed requirements, and an OpenGL 3.3-capable driver are needed when running from source.
  2. Open something interesting. Select File → Open Model… (Ctrl+O) and choose a .3d or .3do file. A car is an excellent beginning. A complete speedway may make your computer reconsider its career.
  3. Look around. Drag with the left mouse button to orbit, turn the wheel to zoom, or choose View → Side for an exact orthographic side view.
  4. Examine the source. Choose View → Show .3D Source. Click a vertex or polygon in the viewport to jump to its corresponding declaration.
  5. Make one small change. Edit a coordinate or color in the source. After a brief pause, valid source recompiles and updates the preview. If it cannot compile, the editor keeps the last valid model visible.
  6. Keep your work. Use File → Save .3D Source As… to save editable text, then File → Export Compiled 3DO… (Ctrl+E) to create a separate binary. Try that binary in ICR2 before celebrating.
Tip: For a car, start with a side view and a tracing reference. For a track, start with the Track workspace and inspect the section-detail settings.

2. Opening, Saving, and Exporting

Opening a file

Choose File → Open Model… to open either a standalone text .3D file or a compiled .3DO. Opening a binary creates editable N3 source for the root geometry. Original text labels and comments cannot be recovered from a compiled file; generated pointer names are used instead. Open Recent remembers successfully opened files, and Reload Model from Disk reopens the current model after confirmation if source has unsaved edits.

The two kinds of output

CommandWhat it savesWhen to use it
Save .3D Source (Ctrl+S)Editable N3 text, preserving your authored declarations and comments.Keep a master copy or save unfinished work. The first save requests a destination; later saves reuse that chosen path.
Save .3D Source As… (Ctrl+Shift+S)A new text file at a destination you choose.Create another revision without replacing your previous source.
Export Compiled 3DO… (Ctrl+E)A validated, newly compiled binary .3do.Install a model for testing in the simulator. Source errors or unfinished validation prevent export.

A * after the filename in the window title means the source has unsaved changes. The editor asks before discarding such changes when opening, reloading, or exiting. It also protects the original model from unintended overwrites.

Do not confuse Save with Export. Saving a text source does not install it in the game. Exporting recompiles the model and may change binary record offsets, order, and structure. It is not an in-place binary patch. Back up the original.

See also: Editing .3D Source · Render diagnostics

3. The Main Window

The left portion of the application displays the 3D model. The adjacent .3D Source pane contains the editable file. Model-specific controls live in the Model Settings dialog; other detailed options live under View and Assets. There is no permanent everything-and-the-kitchen-sink inspector.

MenuYou'll find…
FileOpen, recent files, reload, save source, export compiled 3DO, exit.
EditUndo/redo, text editing and Find, rename pointer, scale model, split polygon, apply source now.
ViewCamera presets, perspective, Fixed Camera, rendering modes, source visibility, display options, colors, diagnostics, and Load Error Log.
ModelCar, Track, or Object workspace; model and workspace settings.
AssetsPalettes, textures, external objects, appearance overlays, tracing photographs, and MIP/UV browser.
HelpThis manual, a quick keyboard/mouse reminder, and About.

Select a different workspace with Model → Workspace. Changing workspace changes the available diagnostic controls; it does not rewrite the model. An automatic workspace hint can be based on a recognized model type, but the file name alone is not proof of what the geometry represents.

Camera controls

Use View → Fixed Camera to examine the geometry from a specific raw Papyrus XYZ position. Edit its coordinate fields under Advanced Diagnostics; the initial fixed eye is (0, 0, 5000). Fixed Camera forces perspective and changes the meaning of mouse-wheel zoom to field of view. Turn it off to resume the orbit camera.

The XYZ helpers

A small red X, green Y, blue Z direction indicator appears at the bottom-left of the viewport. Extended axis guides can also cross the camera focus. Enable or disable them independently under View → Display Options. The guides may be anchored to the view focus, bounding-box center, or raw model origin under Display Settings. They are only onscreen guides and never become part of a compiled 3DO.

Hint: The side orthographic view uses Y horizontally and Z vertically. Excellent for tracing a race car. Less useful for determining which end of an oval is Turn One.

5. Working with .3D Source

Use View → Show .3D Source to open the editor. A source file consists of named vertex, polygon, material, object, and drawing-order declarations. As you type, the editor validates and recompiles after a brief idle delay. Edit → Apply .3D Source Now requests immediate compilation. Invalid source reports an error without replacing the last valid viewport.

A small N3 example

3D VERSION 3.0;
a: [<0,0,0>];
b: [<6000,0,0>];
c: [<0,6000,0>];
face: POLY <44> {a,b,c};
root: LIST {face};

In source, vertex XYZ values are raw Papyrus units unless an explicit or inferred coordinate scale applies. Do not interpret every numeric value as feet. In N3 source, a comment such as % ICR2_COORD_SCALE: 6000 can specify the authored-unit conversion. UV coordinates use texture texels, not normalized 0–1 coordinates.

Find, filter, and get syntax help

Edit → Find in .3D Source… (Ctrl+F) searches the full document. The Filter statements chooser can show only vertices, POLYs, BSPs, MATERIALs, or other declaration categories; filtering does not delete hidden source lines. Double-click a filtered statement to edit it, Ctrl+Enter to commit, or Esc to cancel. Choose Show full source at selected line to return to unrestricted editing.

Cursor-sensitive N3 help appears below the editor. Press Ctrl+Shift+Space or use the source pane's ? button for the longer syntax description. This is command help, separate from the manual you are reading.

Keeping source understandable

Choose Edit → Rename Selected Pointer… or press F2 on a declaration to rename its label. The default automatic reference update also adjusts references to that label. Comments and original declaration names belong in your editable .3D file; they do not survive inside a compiled .3DO.

6. Selecting and Inspecting Geometry

The Pick selector above the viewport offers Vertices and Polys. Click a root-model vertex to select its yellow marker and navigate to its named declaration. Click a polygon in Polys mode to select its source row. Referenced external DYNAMIC children cannot be edited through the root source panel.

Move the source cursor into a polygon declaration to see that polygon highlighted in the viewport. A row shaded green is included by current BSP/LOD selection; a salmon row is excluded. Inclusion is not the same as actual on-screen visibility—another surface may still cover it.

Vertex labels above the viewport can display All, Visible only, or Selected poly pointer names. For BSP declarations, the source inspection overlays show three plane points and the source's winding direction. These markers are diagnostic only.

Did You Know? When a polygon is missing, it may be hiding behind a BSP branch, a distance switch, or another polygon. Blaming the video card is traditionally the fourth step.

7. Editing Geometry

Move a vertex with the mouse

  1. Pick Vertices, then click a named root-model vertex.
  2. Enable Move vertex above the viewport.
  3. Drag a red X, green Y, or blue Z arrow. Only that coordinate changes. Hold Shift for ten-times-finer movement; press Esc before release to cancel.
  4. Release to apply the new XYZ to the canonical source and recompile. Use Ctrl+Z to undo a completed move.

Drag movement snaps in raw Papyrus units. Choose a step of 1, 10, 100, or 1000 under View → Display Settings. An axis pointing straight into the camera cannot be dragged; change your view. Named root vertices only—anonymous inline points and external child vertices are not movable this way.

Symmetrical vertex editing

The optional Symmetrical vertex editing option above source is off by default for each new model. Choose a mirror plane (X, Y, or Z equals a specified value), and the editor can find an existing matching vertex on the opposite side as you edit XYZ. It changes coordinates only, preserving UVs and comments; ambiguous or missing counterpart matches produce prompts or warnings. It does not generate a missing half of a model.

Split a polygon

  1. Choose Edit → Split selected Polygon…, then pick a root-model polygon.
  2. Choose either a cut between two edges at chosen fractions, or a diagonal between existing nonadjacent vertices.
  3. Inspect the preview and seam warnings, then confirm Split polygon.
  4. Review the source change and compile result. Check adjacent seams and BSP planes manually if necessary.

Splitting makes an undoable source edit; it does not automatically save or export. Some anonymous or complex nested polygons cannot be safely rewritten. The editor refuses those cases rather than guessing.

Scale the model

Choose Edit → Scale Model…, enter a positive multiplier or divisor, and apply a uniform XYZ scale about raw origin (0,0,0). Relevant placements, sprite sizes, and SWITCH DISTANCE values are adjusted where supported; UVs, palette colors, and external child geometry are not stretched. Undo reverses the source change.

8. Tracing a Photograph or Blueprint

Reference images make it easier to model a car profile, building elevation, or object whose proportions are known. The image is a preview behind the 3D model, not a texture or exported polygon.

  1. Open the model, then choose Assets → Load Tracing Reference Image… and select a locally stored PNG, JPEG, BMP, WebP, or TIFF image.
  2. Select Side (Y/Z), Front (X/Z), or Top (X/Y). Click Align viewport to this plane (orthographic).
  3. Use Pick A and Pick B on two known points in the image—for instance, the center of each wheel.
  4. Enter the actual distance between those points in raw Papyrus model units. The image scales and rotates to fit that measurement.
  5. Adjust the U/V origin, rotation, opacity, or units-per-pixel. Use Assets → Adjust Tracing Reference… to reopen the controls.

Save a calibrated setup with Assets → Save Tracing Reference Profile…; restore it later with Restore Saved Tracing Profile…. Profiles store the absolute path to your image, not a copy of the image. If you move the JPEG, the profile cannot find it. Remove Tracing Reference removes the active overlay only.

Pro Tip: Two wheel centers of known separation are more dependable than measuring a race car using its sponsor decals. The marketing department has never been a recognized standards body.

9. Textures, Palettes, and MIP Coordinates

Models can reference MIP texture images, PMP sprites, and PCX palettes. Under Assets choose a MIP folder, an external 3DO folder, a fallback MIP, or a palette. Choose Reload MIPs after changing an asset on disk. A missing file may be reported in the load error log even if the geometry still opens.

Find a texture coordinate

  1. Choose Assets → Browse Model MIPs / U,V….
  2. Select a successfully resolved texture in the list.
  3. Zoom with the mouse wheel or +/−. Choose Fit or 100% as needed; middle drag or Shift+left drag pans the texture.
  4. Click a pixel, then choose Copy U,V. Paste the raw integer coordinates into the relevant source vertex attributes.

Texture coordinates start at (0,0) in the top-left, with U increasing right and V increasing down. The browser is read-only: it does not repaint or write MIPs. Repeat UV (tile MIPs) under View → Display Options controls preview sampling.

Tip: In the 256-color era, the correct palette is as important as the correct polygon. A wrong palette can turn a carefully modeled sponsor into something resembling a breakfast cereal.

10. Cars, Drivers, and Appearance Wrappers

Use Model → Workspace → Car for carshape materials, body MIPs, driver appearance, and external wheel/helmet references. A driver-specific car file may primarily carry a RECOLOR table and MIP assignment rather than its own editable car geometry.

To inspect a driver's paint on your current carshape, open roadcar.3do, indycar.3do, or another editable car component and choose Assets → Apply Individual-Car RECOLOR / MIP…. Select a driver wrapper such as cit74.3do. The overlay affects the preview only. Clearing or replacing it does not change the source, and exporting compiled geometry does not embed the wrapper's livery or RECOLOR records.

Car models may depend on other .3do files and MIPs. If wheels or helmets are missing, confirm the external 3DO and MIP folders and review View → Load Error Log….

11. Tracks, Track Sections, and Onboard Cameras

Use Model → Workspace → Track and open Model → Track Settings… for track-specific options. Recognized track models may have indexed section tables with HI / MED / LO detail slots. Fixed detail modes let you inspect one tier; Camera window (HI / MED / LO) follows the camera position if suitable DLONG section metadata exists. If metadata is absent or ambiguous, choose a global tier instead.

The Track settings include per-direction windows for high, medium, and low-detail sections. The default adaptive preview uses 8 nearby HI sections in each direction, then 5 MED each way, then 3 LO each way. These are CAD preview choices, not a promise about the original game engine's rendering limits.

Driving the TRK camera

When the tool finds a matching .trk next to a recognized track model, TRK camera — follow racing direction becomes available. This is a read-only camera guided by the physics course centerline, with local banking. Click the viewport first, then use:

KeyTRK camera movement
W / ↑Forward along DLONG (racing direction)
S / ↓Backward along DLONG
A / ←Left (positive DLAT)
D / →Right (negative DLAT)
Shift + directionMove five times faster

The Track dialog displays DLONG, DLAT, section and bank information. Disable TRK camera to return to the previous orbit view. A missing or malformed matching TRK does not prevent the model geometry from opening.

Horizon and road markings

If a valid horiz.3do or horiz.3d is discovered, a Skybox preview may be enabled in Track settings. Its horizon eye position is adjustable without editing the file. Recognized track surface detail markings are handled by the viewport's depth-biased preview pass to reduce z-fighting; this also does not modify source or compiled track data.

12. Rendering Modes, BSP, and Detail Switches

Select View → Rendering Mode to compare drawing behaviors. The model may look different in each mode; this is precisely why multiple modes are provided.

ModePurpose
Papyrus drawing order (no depth)Draw selected surfaces back-to-front using the editor's BSP traversal; helpful for analyzing painter-style ordering.
BSP selection + depth testingApply the editor's BSP selection but use OpenGL depth for surface occlusion.
All polygons + OpenGL depthInspect geometry regardless of ordinary BSP selection, while retaining relevant track detail-tier handling.
Wireframe (polygon outlines only)View edges without filled faces or textures. Useful for spotting vertices, topology, and errant polygons.

SWITCH DISTANCE / RES controls the model's available levels of detail. Automatic mode estimates distance from the camera, Manual uses a chosen distance, and All levels is for diagnostic inspection. The filtered-source pane can limit results to active distance branches, which does not necessarily mean those faces are actually visible.

For a polygon that disappears at one camera angle, inspect its FACE/BSP plane and source vertex winding. FACE, BSPF, BSPA and related structures determine which branch the CAD preview traverses. The selected source plane can show its three point markers and directional arrows.

Compatibility notice: The preview is reverse-engineered and not game-exact in clipping, transparency, sprite rendering, draw budgets, or all LOD decisions. Saving a recompiled track is not a substitute for validating it in ICR2.

13. When Things Go Wrong

ProblemWhat to try
The model is blank or the program cannot create a viewport.Check Python requirements and an OpenGL 3.3-capable graphics driver. Use View → Frame All. For a complex track, confirm the correct section tier and rendering mode.
Textures, wheels, or an external building are missing.Check Assets → Select MIP Folder / External 3DO Folder. Open View → Load Error Log… for missing filenames and details. Try Reload MIPs.
My changes are not visible.Look for source validation errors, use Apply .3D Source Now, and check whether the polygon belongs to an inactive BSP/RES branch. The viewport keeps the last valid geometry after an error.
I've moved a vertex, but the wrong vertex moved too.Inspect the optional Symmetrical vertex editing setting; it may intentionally move a matched counterpart. Undo and turn symmetry off if unwanted.
I cannot drag a particular vertex.Use Pick → Vertices and Move vertex. Only named, editable root-model vertices work. Rotate the camera if the desired axis points directly at you. Invalid or still-compiling source disables movement.
A tracing profile cannot find its picture.Put the image back at the saved absolute path or load it again and save a new profile. The library stores locations, not image bytes.
Export Compiled 3DO is unavailable or fails.Wait for source validation, correct the reported source error, and select a separate destination. Saving unfinished text is allowed; compiling invalid text is not.
The model looks fine in CAD but not in the simulator.Inspect original BSP/LOD hierarchy, external asset naming and source winding. Test in-game. A successful desktop preview cannot prove engine compatibility.

Use View → Load Error Log… → Copy Log to preserve diagnostic details. For issues with source syntax, use the cursor-sensitive N3 help in the source editor.

Technical Support, 1995 Style: Have you tried turning it off and on again? If so, excellent. Now check the error log—we have considerably better information than a telephone hold queue.
